# 结果包的共享校验

`multi` 写完结果后、`correlate` 和 `report` 消费前均调用 `cli/validation.mjs`。索引版本、整体/观测点完整状态、唯一采集器及视图、秒窗口、缺档、计数和基线共用同一套规则。

仅接收输出模式 **2.0**。历史合法 2.0 包可以省略可选的 SHA-256 与 `correlation_key`；缺少键时由 MoonBit 根据结构化前后状态重算。已提供的键必须与核心计算结果完全匹配。不能通过删除哈希来绕过语义校验；缺少哈希仅表示没有文件字节完整性证明。其他主版本明确失败。

声明的明细必须是包内相对路径；先验证词法路径，再验证真实路径，防止不存在路径或符号链接绕过边界。声明的 SHA-256 必须合法且匹配。完整观测点必须有可读变化明细；部分观测点可缺少尚未生成的文件，输入仍标为 `partial`。存在的坏文件不能因输入部分完成而忽略。

变化逐条验证类型、规范前缀、peer ASN/IP、方向、Path ID、当前及前后状态来源。来源记录号/偏移为规范十进制 Int64 字符串，事件索引非负。缺失微秒视作零；显式微秒只接受 0–999999，拒绝负数、null 或越界值。窗口包含完整起止秒，前状态可以早于窗口。最终状态可以来自基线或预热，但不能晚于结束秒。

提醒计数必须与变化流一致；时间线嵌套变化的时间、身份、来源及语义序列必须与变化文件一致；最终缓存/活动数量与索引统计一致。时间线的单文件内存限制仍为 64 MiB。

关联匹配键仅描述相应变化类型的规范化转移。去重要求更严格：同一来源位置还要比较 peer、方向、Path ID（缺失与 0 不同）、时间、完整规范化前后属性及前后来源。冲突明确失败，不能把同一位置的不同证据静默当作重复。语义解释都来自 MoonBit，JavaScript 不维护另一套路径/属性规范化规则。

验证见 `tests/validation.test.mjs`：同来源各身份字段冲突及倒序、微秒端点、过期/伪造关联键、窗口外输入、计数、部分缺文件、旧 2.0、路径越界和符号链接。两个消费入口对同一坏结果包给出一致的错误结论。
