# 错误、部分结果与资源限制

CLI 成功退出码为 0，读取、解压、解析、容量和输出失败均为 1。断开的 stdout 管道也以非零状态报告 EPIPE；磁盘满、权限错误等不会静默当作成功。

`parse` 和 `changes` 流式输出，可能在后续记录失败前已写出合法行。错误时 stderr 提示标准输出可能只包含部分结果；不能仅凭这些行可解析就认定档案处理完整。CSV 可能只有表头。`stats`、`aggregate`、`timeline` 和 `snapshot-diff` 在输入处理成功后才写结果对象。输出过程中失败仍可能留下不完整字节，应同时检查退出状态。

stdout 仅承载 JSON/CSV 数据，错误与诊断写到 stderr。成功时的处理数量及 `diagnostics` 报告不是失败时的完整性保证。消费者应保存退出码和 stderr；shell 重定向不会把失败结果自动变成完整报告。

## 位置含义

| 位置 | 含义 |
| --- | --- |
| 输入文件 | 实际读取的路径或标准输入 `-` |
| 记录序号 | 当前文件中从 1 开始的 MRT 记录号 |
| 文件偏移 / 记录偏移 | **解压后**记录起点；不是 gzip/bz2 压缩字节偏移 |
| 解析器局部偏移 | 当前解析组件输入中的位置，不能直接与文件偏移相加伪造绝对字段位置 |

完整记录内部的格式错误同时给出记录号、记录起点与局部位置。分帧阶段的 EOF 截断和超长头只给出记录起点，不伪称存在组件内偏移。缺失必需属性没有实际字段字节，使用属性块起点 0。输出 I/O 错误标记为输出失败，不错误归因为某个 BGP 字段。

## 资源和失败边界

- MRT 单记录 payload 最大 16 MiB；超限头在分配该 payload 之前拒绝。
- `StreamDecoder::feed` 单分块最大 1 MiB，EOF 有残留则报截断；失败实例必须重建。
- 分析的 `--capacity` 包括活动及保留的撤回路由键；超限明确失败，不静默淘汰旧状态。时间线另限制历史路径与条目数。
- 无效 peer 索引、重复属性、非法属性标志及长度、缺失 UPDATE 必需属性均失败。范围外类型和地址族仅在其已知公共结构可读取时跳过并计数，不能用“未知类型”掩盖已知头部的截断。
- 损坏 gzip/bz2、缺失解压器或文件读取错误同样失败；成功解码若干记录不等同于压缩流已通过末尾校验。

`tests/failure_contract.test.mjs` 覆盖解析后部分输出、截断记录、错误 peer 索引、容量/长度上限、gzip CRC、快照输入错误、实际关闭的输出管道，以及注入 ENOSPC/EACCES/EPIPE 写回调错误。既有 CLI 测试另覆盖 bz2 损坏和缺失解释器；错误不会混入 JSON/CSV 数据流。
