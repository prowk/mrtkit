# 按 peer 分区的完整状态回放

```sh
node cli/mrtkit.mjs replay-disk --manifest 单观测点清单.json --output 新目录 --rss-mib 2048 --disk-mib 122880 --memory-mib 64 --keep-partitions
```

清单沿用 [multi](multi-collector.md) 的 1.0 格式，每次提供一个明确的采集器/视图。输入文件路径不能重复；路径、类型、时间范围和可选 SHA-256 仍明确声明。输出仍为 2.0 `collector_replay_bundle`，可直接供关联与报告消费。

## 状态和来源语义

全部原始文件先由 MoonBit 解码至 EOF。RIB 按完整 peer 身份拆出原始条目，只重写临时 MRT 的长度和条目数；属性、前缀和原始事件索引完整保留。每个 peer 的双向更新与状态事件存于同一个二进制分区。逐分区使用原来的 MoonBit 分析器回放，不在 JavaScript 中重写协议或路由分析规则。

同一 peer 的全部输入都处理完才结束其分析器，因此重置、乱序水位、撤回缓存和波动窗口不会因分区而消失。所有结束路由，包括撤回缓存，均写入最终状态文件；只有原有会话重置规则会清除相应缓存，不加入过期淘汰。输出是结束快照，不是可直接恢复内部波动水位的运行检查点；追加档案时须重放完整输入序列。

记录号、偏移和事件索引指向**原始压缩档案的解压记录**。临时分区帧的物理位置不会冒充来源。变化流在外部排序后恢复原始文件、记录和事件顺序，同一事件按路径、起源、属性、波动顺序输出。

## 资源与完整性

默认预算为 2 GiB RSS、120 GiB 新建临时/结果文件和两小时；单个 peer 及主进程都检查 RSS。各 peer 子进程串行运行。对每个作业，将它退出时的父进程历史峰值与该子进程生命周期峰值相加，取所有作业的最大值；再与全部阶段的父进程峰值取最大，得到保守的 `peak_rss_upper_bound_bytes`。另记录实际采样的同时 RSS。不会把已退出的子进程峰值与后续独占校验阶段峰值相加。固定真实负载使用 gzip，不启动外部解压器；bz2 的 Python 解压辅助进程不计入此父/peer 资源字段。单个 peer 本身过大仍可能失败，不声称任意表大小都能进入预算。

分区文件最多 4096 个，最多 64 个写句柄，写缓冲最多约 4 MiB；全局容量不会被拆分绕过。容量大于全部原始路由事件数时使用严格上界证明，否则写出每 peer 的缓存数量变化，按原始顺序外排复算全局峰值，超限即失败。

输出状态逐块导出、逐行规范化，记录完整文件哈希、活动/缓存数量和可按分区组合的逐行 SHA-256 求和/异或指纹。另有便携指纹仅将物理目录替换为“输入序号/档案名”，完整输出仍保留原来源路径。成本分别记录原始解析及分区、再次解码/分析、变化序列化、写盘、最终状态序列化/指纹和结果包复核。

`complete` 只在全部文件、导出、共享校验、清理及预算检查完成后发布。失败保持 `partial`、非零退出，并清理本次临时目录；原输入不会修改。Ctrl+C 取消会终止当前 peer 子进程。输出目录必须不存在。

`--keep-partitions` 将有哈希的 `.mrtp` 二进制源分区及位置映射留在 `partitions/`，便于独立核查；否则临时分区在最终状态写出后移除。此选项不丢弃完整结束状态。

## 验证范围

[组件剖析](../validation/state-components.md)提供选择磁盘分区的量化依据。`tests/disk-replay.test.mjs` 与完整内存回放逐项比较变化顺序、状态、计数和来源，还通过独立 1200 事件模型核对显式/缺基线、ADD-PATH、预热、属性和路径变化、撤回、重置及乱序。固定全量输入已满足预先确定的资源预算，见[三轮完整验收](../validation/full-replay.md)；该结果仍限定于记录的输入和环境。
