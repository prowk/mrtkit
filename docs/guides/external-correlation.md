# 有界内存关联与分离输出

```sh
node cli/mrtkit.mjs correlate --input .validation/multi/index.json --external --output .validation/correlation --window 60 --memory-mib 64 --disk-mib 8192
```

输出目录必须不存在。`--memory-mib` 是排序运行预算：最多四分之一用于序列化行载荷，余量用于对象、排序和读取缓冲；它不是整个 Node 进程的 RSS 上限。`--disk-mib` 限制新建的排序临时文件及结果数据，输入文件不计入。预算不足明确失败，取消支持 Ctrl+C；临时目录关闭句柄后清理，结果索引标为 `partial`。最多 16 KiB 的失败诊断收据单独保留，不受已耗尽的数据预算阻止。

## 等价规则与资源边界

先按完整来源 ID 外排去重并检查冲突，再按语义签名和微秒顺序外排，逐组执行固定半开窗口。与内存模式使用同一个核心语义键、证据比较、排序器和质量汇总函数。归并扇入固定，排序运行按层及时合并，最多 54 层；不会为所有观测、所有 peer 或所有临时文件保留一个随数据规模增长的对象集合。覆盖 peer 另外外排去重计数，单个巨大关联组也不会积累全部观测对象。

`index.json` 包含完整/部分状态、输入索引哈希、全局计数、输入质量、资源开销和明细文件完整性信息。`groups.jsonl` 每行一个摘要：首次/末次观测、窗口结束、覆盖采集器/peer、提醒数量和未观测质量。`observations.jsonl` 流式保存完整关联观测位置及来源，通过 `group_id` 引用摘要。

组 ID 为 `group-` 加上 `SHA256(语义签名十六进制 + 换行 + 首次观测 Unix 微秒十进制)`，输入重排不改变标识。观测本身也有稳定来源 ID。摘要的 `legacy_id` 保留原单 JSON 的分组顺序。`reconstructCorrelation` 仅用于显式的小结果兼容重建，默认最多 100 万条；它检查文件哈希、引用和计数，能重建原有 JSON 结果。正常外部处理不调用这个内存重建接口。

## 验证

`tests/correlate-external.test.mjs` 逐项比较混合微秒、语义、重复、缺档和基线的多轮落盘结果与内存结果；验证冲突、预算失败、取消和临时文件清理。`tests/external-sort.test.mjs` 检查多级归并与内存排序一致。

`node scripts/correlation_scale.mjs --output 新目录` 生成固定的 1,000,100 条合法合成变化通知，超过内存模式默认容量。预算为 512 MiB 进程 RSS、8 GiB 排序/输出磁盘和 20 分钟，实际文件和计数会重新读回核对。它是规模测试，不是真实网络档案。正式测量证据在完成验证后存入验证目录。

固定提交 `26a33a5` 的测量已完成：1,000,100 条观测，约 190.36 秒，核验阶段在内的峰值 RSS 约 253.38 MiB，新增临时/输出峰值约 1.85 GiB。输入、两类输出及被测代码 SHA-256 均已复核，见[原始测量收据](../validation/correlation-scale.json)。该结果仅描述这一个固定合成负载，不表示任意文件大小、属性长度或全部关联分布的性能。

关联仍只表示所选采集器观测到相同语义变化的时间共现，不推断真实传播时延或因果。
