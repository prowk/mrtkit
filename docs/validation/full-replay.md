RSS 包括基准控制器、回放父进程与串行 peer 子进程。上界取“全部阶段父进程峰值”及“每个 peer 作业结束时父进程历史峰值加该子进程生命周期峰值”的最大值，再加控制器峰值。这一计算覆盖实际并发阶段；没有将已退出的子进程峰值与后续独占阶段峰值相加。gzip 解压在进程内执行。磁盘指标同时包含前几轮仍保留的输出，未逐轮清空以降低记录值。

测量时机器还运行其他验证任务，因此耗时是共享机器上的实测结果，不能视为隔离吞吐量。单个 peer 仍需完整进入其子进程内存，不保证任意更大输入都满足同一预算。

[历史独立核对收据](full-state-independent.json)来自数据全部核对成功、但资源 RSS 上界检查被拒绝的尝试。该旧尝试保持失败。后续成功轮次只有在实际文件的完整 SHA-256、字节数、行数与独立核对数据一致，且统计逐项一致时，才可绑定该数据证明；哈希不一致的输出必须重新独立核对。

## 复现与保留范围

先按[验证导航](README.md)取得并核对全部原始档案，再运行：

```sh
node scripts/full_replay_benchmark.mjs --output 新三轮目录
python scripts/full_state_reference.py --manifest 新三轮目录/manifest.json --output 新参考目录 --bundle 新三轮目录/run-1/index.json
node scripts/publish_full_replay.mjs --input 新三轮目录 --reference 新参考目录/verification.json
```

独立模型需要额外 SQLite 临时空间；它的建模成本单独记录，不计入被测回放进程树。具体输出文件名和更多选项可用 `python scripts/full_state_reference.py --help` 查询。汇总程序要求三轮完整通过，并重新读取实际输出与输入哈希，检查被测源码快照和实际回放依赖。

发布附件保留被测回放源码及编译桥接文件快照、独立模型/核对源码快照，均附 SHA256SUMS。历史[整表驻留失败](full-state-benchmark.md)、[RSS 上界拒绝记录](full-replay-rss-rejected.json)和中断收据继续保留。原始档案和多 GB 输出只保存在本地忽略目录。最终核验后重新哈希全部六份状态/变化文件，保留 run-1 的完整可消费结果，清理 run-2/run-3 的四个重复大文件，共 35,702,677,444 字节；各轮索引及测量仍保留，见[清理收据](full-replay-retirement.json)。
