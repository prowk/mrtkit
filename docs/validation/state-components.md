# 完整状态的剩余内存开销

[原始三轮剖析与中位数](state-components.json) · [固定负载及预算](state-resource-target.md)

剖析使用固定提交 `13969e9` 的协议构建；从该提交独立重建的产物 SHA-256 与被测产物相同。仅在编译文件末尾追加会话检查入口，读取完成之后在**独立进程副本**中删除组件引用，前后执行完整 GC。生产分析器没有被修改。表中是按顺序移除引用后释放的保留堆，不是对象的固有大小，也不能在不同移除顺序之间直接比较；原始数据保留小幅负值噪声及独立 ArrayBuffer 变化。

| 状态数 / 撤回状态 | 228,292 / 0 | 46,520 / 4,873 |
| 初始 GC 后 JS 堆 | 248.16 MiB | 88.44 MiB |

| 剩余活动路由键 | 14.28 MiB | 2.69 MiB |

| 剩余事件及时间水位 | 48.52 MiB | 14.72 MiB |
| 路由查找索引 | 19.68 MiB | 3.70 MiB |

RIB 检查点只读取前 25,000 条记录，是组件剖析，不代表完整回放成功。其 228,292 个状态含 228,292 个来源对象、42,492 个共享属性集，路由键合计 10,284,197 个字符。UPDATE 场景完整读至 EOF，但没有初始 RIB。两种场景都不替代完整 RIB 加更新的成功验收。

保留一块 128 条状态的 JSON 及解析后对象，RIB 检查点额外约 338 KiB，UPDATE 场景约 777 KiB；这说明分块导出的临时成本受块大小限制。它不是整个最终状态导出的耗时或内存测量。

共享属性负载仍是最大部分；来源、路由记录、键和双重索引也随路由数量增长。单独回收属性池索引或压缩键不足以保证完整表进入 2 GiB。后续实现选择按完整 peer 身份分区，并把完整逻辑状态保存到磁盘；同一 peer 的双向事件及会话重置保持在一个分区，避免破坏跨方向重置水位。不会用过期回收或丢弃来源来换取预算。

复现：`node scripts/profile_state.mjs`，再按 JSON 中的固定提交独立重建源码并执行 `node scripts/publish_state_profile.mjs`。输入来自固定目标清单，剖析中的破坏性操作只针对加载到独立 Node 进程中的临时分析器副本；不改原始 MRT、项目源代码或正式回放结果。
