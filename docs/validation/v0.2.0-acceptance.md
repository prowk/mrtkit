# v0.2.0 验收

本记录区分代码与数据验证、资源验收和真实浏览器验收。工具版本、机器输出 schema 和紧凑流编码分别为 0.2.0、2.0、`full_jsonl_v1/event_refs_v1`。本地申报材料、任务草稿和验证大文件均排除在仓库与发布包之外。

| 范围 | 证据与结论 |
| --- | --- |
| 来源冲突、时间、版本、计数与语义键 | `tests/validation.test.mjs` 覆盖同来源冲突及输入重排、无 Path ID 与 ID 0、秒/微秒边界、非法窗口、伪造语义键和旧 2.0；消费者使用[同一校验](../reference/bundle-validation.md) |
| 完整逻辑状态存储 | [组件剖析](state-components.md)量化属性、键、来源、peer 索引、撤回缓存和导出成本；磁盘分区不丢弃状态，测试与完整内存模型逐项比较状态、顺序、来源、重置、乱序及全局容量 |
| 独立全量数据重算 | 13 个完整档案、1,597,926 条原始记录、11,946,097 条路由事件和 749 条会话事件；独立模型核对 11,093,122 条结束状态、1,197,552 条提醒及来源，三轮实际输出哈希、行数和统计重新核验一致，见[独立绑定收据](full-state-verified.json)。[历史核对](full-state-independent.json)对应旧 RSS 拒绝尝试，其资源失败状态保留 |
| 三轮固定资源目标 | [目标](state-resource-target.md)为 2 GiB RSS、120 GiB 新增临时/结果磁盘、每轮两小时，无前缀或 peer 缩减。三轮全部通过，耗时约 39.2 / 35.4 / 36.3 分钟，最高 RSS 上界约 1.79 GiB、磁盘峰值约 63.28 GiB，见[完整结果](full-replay.md)；[旧 RSS 上界拒绝记录](full-replay-rss-rejected.json)保持失败 |

## 大报告性能目标

[大报告目标](report-performance-target.json)预先固定首屏三秒、组合筛选三秒、翻页一秒、浏览器进程树 RSS 1 GiB、重复三轮。

## 复现与结果管理

```sh
npm test
moon test --target wasm --deny-warn
moon test --target wasm-gc --deny-warn
python -m unittest discover -s scripts -p test_compare.py
python -m unittest discover -s scripts -p test_full_state_reference.py
python scripts/verify_case.py
node scripts/full_replay_benchmark.mjs --output 新完整回放目录
node scripts/compact_benchmark.mjs --output 新紧凑测量目录
node scripts/report_workload.mjs --output 新大报告目录
```

三轮完成后，先用 `scripts/full_state_reference.py` 对全部原始档案建模并核对输出；再运行 `node scripts/publish_full_replay.mjs --input 三轮目录 --reference 独立核对.json`。汇总器要求三轮均完整通过，重新核验实际输出哈希、行数、源码快照、输入哈希和每轮统计。已独立逐行验证过的数据可以通过完全相同的文件 SHA-256 绑定新轮次；旧参考尝试的资源失败状态会原样保留，不能冒充新轮次的资源结论。

完整回放、编码和关联大文件只留在被忽略的 `.validation/`。输出核验后保留一份必要负载及哈希/指纹收据，清理重复文件；中断与预算失败收据保留，不能通过删除失败记录改变验收结论。独立模型和数据核对使用的确切源码快照随发布附件提供。
